# 九溪（JiuXi）· 架构文档

> 本文说明九溪的技术架构与运行原理，面向协作开发者、技术伙伴与后续维护者。
> 配套文档：调研报告、PRD、实施计划。阅读完本文即可理解「九溪为什么这样搭、各模块如何协作、如何扩展与维护」。

---

## 1. 设计约束回顾

九溪的架构完全服务于以下硬约束，任何技术选型都不应偏离它们：

| 约束 | 含义 | 架构上的体现 |
|---|---|---|
| 不会后端 | 不写/不运维服务器与数据库 | 纯静态站点 + 可选无服务器函数，无传统后端 |
| 只用手机 | 大部分时间在移动端操作 | 内容以仓库内 Markdown 存储，手机浏览器即可编辑 |
| 推送 GitHub | 代码与内容进 Git 仓库 | 源码进仓、CI 自动构建出静态站 |
| 实时资讯 | 新闻/时间线要常新 | 动态内容走浏览器端实时抓取 + 本地缓存 |
| 液态玻璃 + 多主题 | 视觉是重点 | 自研玻璃组件 + CSS 变量多主题系统 |

**核心决策**：用「纯静态生成（Astro）+ 浏览器端实时聚合 + 仓库内策展数据 + CI 自动部署」组合，把「无后端、可手机维护、长期可演进」三件事同时达成。

## 2. 总体架构

```

│                      访客浏览器                            │

│   ├─ 玻璃组件（GlassCard / GlassButton / GlassPanel）       │

   │ 公开数据源        │          │ GitHub 仓库         │
   │ Google News RSS  │          │ ・源码（Astro）      │
   │ freenewsapi / HN │          │ ・策展内容（MD）      │
   └────────┬────────┘          └─────────┬──────────┘
            │ 遇 CORS（仅副站）            │ push / 编辑
            ▼                              ▼
   ┌─────────────────┐          ┌────────────────────┐
   │ 第三方 CORS 代理  │          │ GitHub Actions     │

   └─────────────────┘          └─────────┬──────────┘
                                    ▼
                          ┌────────────────────┐
                          │ Cloudflare Pages   │
                          │  （主站，全球 CDN）  │
                          │ GitHub Pages       │
                          │  （备用副站）        │
                          └────────────────────┘
```

### 两类数据流

1. **动态流（AI / 新闻 / 科技 / 游戏）**：浏览器端运行时实时抓取公开源 → 本地缓存 15 分钟 → 渲染。天然实时，**无需重建站点**。
2. **策展流（时间线 / 工具箱 / 读书）**：你改 GitHub 仓库里的 Markdown 数据文件 → 推送 → GitHub Actions 自动重建并部署 → 上线。

两条流互不阻塞：动态流坏了不影响策展内容，策展流更新也不会打断实时资讯。

## 3. 技术栈与分层

| 层 | 选型 | 职责 |
|---|---|---|
| 框架 | **Astro 5** | 内容优先的静态生成；默认零 JS；Content Collections 管理策展数据 |
| 样式 | **Tailwind CSS 4**（含 `@tailwindcss/vite`） | 原子化样式 + 快速开发 |
| 语言 | **TypeScript** | 类型安全 |
| 运行时 | **Node.js 22+** | 本地/CI 构建 |
| 内容 | Astro Content Collections（Zod schema） | 时间线 / 工具箱 / 读书的结构化数据 |
| 数据源 | Google News RSS、Hacker News（Algolia）、freenewsapi、allorigins（CORS 兜底） | 动态资讯抓取 |
| 部署 | GitHub Actions + Cloudflare Pages / GitHub Pages | 双站自动构建与发布 |

**分层视图**：

```
展示层   src/pages/*       10 个页面（HTML 结构 + 数据装配）
  └─ 组件层 src/components/*  可复用 UI（导航 / 玻璃卡片 / 按钮 / 资讯板块）
       └─ 布局层 src/layouts/BaseLayout.astro  全站外壳 + 防闪烁 + 导航
样式层   src/styles/*      global / glass / themes / components
逻辑层   src/lib/*         theme.ts（主题）/ feeds.ts（抓取）/ store.ts（本地数据）
内容层   src/content/*     timeline / tools / reading（Markdown + Zod 校验）
配置层   astro.config.mjs / wrangler.toml / .github/workflows/deploy.yml
```

## 5. 前端架构

### 5.1 页面与布局

- **BaseLayout.astro** 是全站单一外壳：定义 `<head>`（含防首屏闪烁的内联脚本）、注入主题变量、挂载 `SiteNav` 与 `ThemeSwitcher`，并包裹页面内容插槽。
- 每个页面（如 `ai.astro`）只负责「取数 + 装配」：策展页面从 Content Collections 读取；动态页面把板块关键词交给 `FeedSection` 在客户端渲染。
- 默认输出**零 JS**：除主题切换、资讯抓取、时间线交互、本地数据这几处必要脚本外，页面本身是静态 HTML，保证首屏快、成本低。

### 5.2 液态玻璃视觉系统（glass.css）

- 核心 = `backdrop-filter: blur()` + 半透明背景 + 内高光/外阴影 + 圆角，营造玻璃质感。
- 对不支持 `backdrop-filter` 的浏览器（如旧版 Safari）**自动降级**为普通半透明毛玻璃，保证可读与美观不崩。
- 玻璃强度（模糊半径、透明度）也作为主题令牌，可在主题间差异化。

### 5.3 多主题系统（themes.css + theme.ts）

- **机制**：在 `:root` 定义默认（明）语义令牌（`--bg / --surface / --text / --text-muted / --accent / --border / --shadow / --radius / --glass-blur / --glass-opacity`），再用 `[data-theme="xxx"]` 逐套覆盖。
- **4 套预设**：晨曦（明）/ 午夜（暗）/ 极光 / 樱粉。
- **theme.ts**：`applyTheme(name)` 写 `document.documentElement.dataset.theme` 并持久化到 `localStorage`；初始化时读取系统 `prefers-color-scheme` 与已存偏好。
- **防闪烁**：`<head>` 内联一小段脚本，在 CSS 与首屏绘制前应用已保存主题，避免白屏/闪主题。
- **可扩展**：新增主题 = 在 `themes.css` 加一段变量 + 在切换器加一个选项，**无需改动任何组件**。

### 5.4 Content Collections 数据层（content.config.ts）

- 用 **Zod schema** 为 `timeline / tools / reading` 三个集合定义结构，构建期即做类型校验，字段写错会构建失败而非悄悄出错。
- 每个条目是一个 Markdown 文件，Frontmatter 写元数据，正文写简介，做到「改一处 = 改一个文件」。
- 字段示例：
  - 时间线：`year` / `month` / `title` / `category` / `source`
  - 工具箱：`name` / `url` / `category` / `description`
  - 读书：`title` / `author` / `rating` / `cover` / `review`

### 5.5 客户端动态抓取与缓存（feeds.ts）

- 维护「数据源 → 板块」的映射：新闻/科技/游戏/AI 对应 Google News RSS（含 `hl=zh-CN`）、HN API、freenewsapi 等。
- **抓取**：客户端 `fetch` 多源并行 + 超时；结果写入 `sessionStorage/localStorage` 并设 **15 分钟缓存**，避免频繁请求与限流。
- **兜底**：某源失败 → 回退到缓存或友好提示，保证页面不空。
- **CORS 处理**：主站（Cloudflare Pages）可挂 Pages Functions 做第一方代理根除跨域；副站（GitHub Pages）走 `allorigins` 等第三方代理兜底。

### 5.6 本地数据层（store.ts）

- 管理访客侧数据：收藏/书签、阅读进度、主题与动效偏好。
- 优先 **IndexedDB**，退化到 `localStorage`；提供导出/导入 JSON、清空缓存等能力（设置与数据页）。
- **隐私**：这些数据只存在于访客自己的浏览器，站点不收集、不上传任何访客信息。

## 6. 部署架构（双站容灾）

采用**主站 Cloudflare Pages + 备用副站 GitHub Pages**，由 `.github/workflows/deploy.yml` 驱动，`push` 即构建并双发。

### 6.1 base 路径处理

两个站点根路径不同，故各自独立构建：

- **GitHub Pages（项目站点）**：固定为 `https://<用户>.github.io/<仓库>/`，构建时注入 `SITE_BASE=/jiuxi/`。
- **Cloudflare Pages（根路径/自定义域名）**：`SITE_BASE` 留空，默认 `base=/`。
- 实现：`astro.config.mjs` 中 `base: process.env.SITE_BASE || '/'`，CI 在 `build-pages` 步骤注入 `/jiuxi/`，`build-cloudflare` 步骤用默认 `/`。

### 6.2 CI 流程（deploy.yml）

四个 job 两两配对、互相独立，任一失败不影响另一：

| Job | 作用 |
|---|---|
| `build-pages` | `npm ci` + `npm run build`（注入 `SITE_BASE=/jiuxi/`），产出上传为 Pages Artifact |
| `build-cloudflare` | `npm ci` + `npm run build`（默认 `base=/`），产出上传为普通 Artifact |
| `deploy-github-pages` | 用 `actions/deploy-pages` 发布到 GitHub Pages（无需密钥） |
| `deploy-cloudflare` | 用 `cloudflare/wrangler-action` 发布到 Cloudflare Pages（需 Secrets） |

> 缺 Cloudflare 密钥时，`deploy-cloudflare` 以 `continue-on-error` 柔性处理，不阻塞副站；密钥就绪后即真正部署。

### 6.3 安全（密钥管理）

- 仅两个 Secrets：`CLOUDFLARE_API_TOKEN`（最小权限：仅 Pages Edit）与 `CLOUDFLARE_ACCOUNT_ID`，存于仓库 **Settings → Secrets → Actions**，由 CI 注入环境变量。
- **密钥永不进仓库代码或构建产物**，不出现在 `git` 历史。
- GitHub Pages 副站完全无需任何密钥。

## 7. 安全与隐私模型

| 维度 | 做法 |
|---|---|
| 访客隐私 | 不收集、不上传任何访客数据；本地数据仅存浏览器 |
| 动态抓取 | 仅走公开数据源（RSS / 公开 API），不依赖私有凭证 |
| 部署密钥 | 仅 CI Secrets；仓库内零明文；token 最小权限 |
| 许可证 | 代码 Apache-2.0；文档与原创内容 CC BY-NC 4.0；第三方保留原许可 |

## 8. 性能与降级策略

- **零 JS 默认**：页面主体是静态 HTML，首屏快、带宽省。
- **玻璃降级**：不支持 `backdrop-filter` 的浏览器自动退化为普通毛玻璃。
- **动效可控**：尊重系统 `prefers-reduced-motion`；设置页提供「减少动效 / 降低透明度」开关，照顾低端机。
- **缓存策略**：动态资讯 15 分钟本地缓存，降低对外部源的依赖与限流风险。

---

## 9. 可维护性与手机协作

- **内容即文件**：时间线/工具箱/读书都是仓库内 Markdown，手机浏览器登录 GitHub 即可编辑、提交，CI 自动上线。
- **模块化板块**：新增/调整板块主要在 `src/pages` 与 `content.config.ts`，主题与组件无需改动。
- **低门槛部署**：一切由 CI 自动化，维护者无需敲命令、无需管服务器。
