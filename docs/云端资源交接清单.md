# 云端资源交接清单（Cloudflare + GitHub）

> 目的：换人、换账号、换设备时，不靠记忆也能把九溪的云端侧完整接管。
> 适用范围：Cloudflare Pages 主站、GitHub Secrets 与 Actions。
> 最后核对：2026-10-18（v1.11.1 RSSHub 接入修正：19 个路由 CI 实测 19/19 可用，源总数 321；架构仍为 v1.8.0 起的纯静态，与 CHANGELOG 对应）。

---

## 一、架构状态（v1.8.0 起）

九溪自 v1.8.0 起是**纯静态站点**——没有 Cloudflare Pages Functions、没有 D1 数据库、没有任何云端运行时接口。

- 所有资讯在 `npm run build` 时由 `scripts/fetch-feeds.mjs` 抓取并注入各页内嵌 JSON（首页 / 热点榜 / 策展页注入聚合数据 `#jiuxi-feed-all`），访客打开即有内容。
- 部署只是把 `dist/` 静态产物上传到 Cloudflare Pages，**不涉及任何数据库写入或 Functions 编译**。
- 历史上曾有的 `functions/api/{feed,history,candidates}.ts`、`scripts/save-history.mjs`、`scripts/ensure-candidates.mjs`、`wrangler.toml` 的 D1 绑定，均已在 v1.8.0 移除。本清单不再涉及 D1 与 Functions 接管。

| 资源        | 名称 / ID             | 位置                                | 用途                       |
| ----------- | --------------------- | ----------------------------------- | -------------------------- |
| Pages 项目  | `jiuxi`               | Cloudflare 控制台 → Workers & Pages | 托管纯静态站（`dist/`）    |
| 生产域名    | `jiuxi-bm1.pages.dev` | 上一行项目的默认子域名              | 线上唯一入口（`SITE_URL`） |
| GitHub 仓库 | `xiaoyu-hue/jiuxi`    | github.com                          | 源码 + Issues + Actions    |

> ⚠️ **同名碰撞提醒**：`jiuxi.pages.dev` 是 Cloudflare 上另一个完全不相干的站点（同名项目被他人注册），**不是九溪**。九溪的域名是 `jiuxi-bm1.pages.dev`，所有文档、UA、`SITE_URL` 均以此为准。评估线上状态时不要访问错域名。

## 二、GitHub Secrets（仓库 Settings → Secrets and variables → Actions）

| Secret                  | 内容                 | 最小权限建议                          | 缺失时的行为                         |
| ----------------------- | -------------------- | ------------------------------------- | ------------------------------------ |
| `CLOUDFLARE_API_TOKEN`  | Cloudflare API Token | **Pages Edit**（勿给账户级 All Edit） | 部署步骤跳过（不红叉），冒烟测试跳过 |
| `CLOUDFLARE_ACCOUNT_ID` | Cloudflare 账户 ID   | —（标识用，非凭证）                   | 同上                                 |

> v1.8.0 起**不再需要 `D1_DATABASE_ID`**——站点已无数据库。若仓库 Secrets 里仍残留该变量，可保留（无副作用）也可删除。

凭证安全约定：

- Token 只从 Secrets 读取，**任何脚本/代码/日志不得硬编码或回显**。
- Token 权限遵循最小化：仅 Pages Edit 即可覆盖全部现有流程（部署）。
- 怀疑泄露时：Cloudflare 控制台 → My Profile → API Tokens 直接**吊销重建**，再到仓库 Secrets 更新，无需改任何代码。
- 轮换建议：随人员变动或至少每年一次。

## 三、两个工作流的分工

| 工作流              | 触发方式              | 做什么                                                                                                     |
| ------------------- | --------------------- | ---------------------------------------------------------------------------------------------------------- |
| `deploy.yml`        | push 到 `main` / 手动 | 质量门禁 → 构建（`npm run build`，含 fetch-feeds 抓取注入）→ `pages deploy dist` → **冒烟测试** → ZAP 扫描 |
| `refresh-feeds.yml` | 每小时 cron / 手动    | 构建 → fetch-feeds 抓取注入最新资讯 → 同样 `pages deploy dist`                                             |

两个工作流的部署 job 共用 `jiuxi-deploy` 并发组，不会交错上传。

### 冒烟测试（deploy.yml，纯静态）

部署完成后自动校验静态站是否真的有内容，把「部署异常 / 注入缺失」转为 CI 红灯：

- `GET /`：HTTP 200 且响应含构建期注入的聚合 JSON 片段 `id="jiuxi-feed-all"`。
- `GET /hot`：HTTP 200。
- `GET /curate`：HTTP 200。

判定规则：

- **红灯**（退出码 1，工作流失败）：任一页面连续 3 次不返回 200 / 首页不含聚合注入——即静态站部署异常（构建失败或注入未生效），需查 deploy job 日志与 Cloudflare 控制台。
- **绿灯**：三页均达标。
- 仅当本次运行真的发生了部署才执行（未配 CF 密钥则跳过，不对线上旧版本误报）。

> v1.7.1 曾有的「D1 写穿核查」「探测 /api/* 端点」步骤，随后端移除已在 v1.8.0 删除。

## 四、控制台操作路径（常见任务）

| 任务            | 路径                                 |
| --------------- | ------------------------------------ |
| 看部署记录      | Pages 项目 `jiuxi` → Deployments     |
| 吊销/重建 Token | Cloudflare → My Profile → API Tokens |
| 看 Actions 运行 | GitHub 仓库 → Actions                |

> 纯静态部署**无 Functions / D1 可配置项**——如控制台出现 Functions 或 D1 相关设置，是 Cloudflare 平台通用能力，与九溪当前架构无关，无需接管。

## 五、本地接管 checklist

接手人按序核对，全部打勾即完成接管：

1. [ ] 被拉入 Cloudflare 账户（或拿到自建账户 + 上述资源迁移方案）
2. [ ] 拿到 GitHub 仓库写权限（push `main` 即触发部署）
3. [ ] 两个 Secrets 已在仓库配置（见表二；缺失时部署自动跳过，不会报错——要主动确认）
4. [ ] 手动跑一次 `deploy.yml`（Actions → Deploy 九溪 → Run workflow），确认冒烟测试绿灯
5. [ ] 访问 `https://jiuxi-bm1.pages.dev/`、`/hot`、`/curate` 验证内容与页面正常

## 六、应急操作

| 症状                       | 第一动作                                                                                  |
| -------------------------- | ----------------------------------------------------------------------------------------- |
| 冒烟测试红灯（首页无注入） | 看 deploy job 的构建日志 → 控制台 Deployments → 核对 `wrangler.toml` / `astro.config.mjs` |
| 线上内容陈旧               | 看 `refresh-feeds.yml` 最近一次运行是否成功（GitHub 高频 cron 可能延迟）                  |
| 需要立刻回滚               | Pages 项目 → Deployments → 选历史部署 → Rollback（静态部分秒级回退）                      |
