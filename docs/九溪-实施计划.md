**数据流两类**
1. **动态流（新闻/科技/游戏/AI）**：浏览器端实时抓取公开源 → 本地缓存 15 分钟 → 渲染。无需重建。
2. **策展流（时间线/工具箱/读书）**：你改 GitHub 仓库里的数据文件 → 推送 → GitHub Actions 自动重建部署 → 上线。

## 1. 技术选型与理由

| 层 | 选型 | 理由（简要） |
|---|---|---|
| 站点框架 | **Astro 5** | 内容优先、零 JS 默认、Content Collections 管理策展数据、易部署 |
| 样式 | **Tailwind CSS 4** + 自研玻璃 CSS | 原子化高效；玻璃效果用原生 `backdrop-filter` + SVG 滤镜 |
| 玻璃组件 | 自研（参考 nikdelvin/liquid‑glass） | 轻量、可控、Safari 降级；不绑定重依赖 |
| 主题 | CSS 变量 + `data-theme` + localStorage | 运行时切换、防闪烁、可扩多套 |
| 托管 | **Cloudflare Pages**（主）/ GitHub Pages（备） | 免费、无限带宽、可做函数代理与定时任务 |
| 无服务器 | Cloudflare Pages Functions（可选） | CORS 代理 + Cron 刷新，仍属「无后端」 |
| CI/CD | GitHub Actions | push 即构建部署 |
| 内容 | 仓库内 Markdown/JSON | 手机浏览器即可编辑，零运维 |
| 部署技能 | github‑pages / cloudflare / publishing‑astro‑websites | Agent 自动部署，你少动手 |

## 4. 各板块实现要点

- **首页聚合**：读各板块「精选」字段，渲染 Bento 卡片；实时卡走 Phase 3 的抓取器。
- **AI/新闻/科技/游戏**：共用 `FeedCard` + `feeds.ts`，仅数据源配置不同；关键词在配置文件集中管理。
- **AI 发展时间线**：数据用 Markdown  frontmatter（年份/月份/事件/类别/来源）；前端按年分组渲染；筛选用类别标签；搜索为客户端文本匹配。
- **AI 工具箱**：数据含名称/链接/分类/简介；标签筛选。
- **读书推荐**：含书名/作者/封面/短评/链接；卡片网格。
- **设置与数据**：纯前端，读写 localStorage/IndexedDB；导出为 JSON 文件下载。

## 5. 主题系统设计细节

- `themes.css` 中：` :root` 定义默认（明）令牌；`[data-theme="midnight"]`、`[data-theme="aurora"]`、`[data-theme="sakura"]` 等各自覆盖。
- 令牌集：`--bg / --surface / --text / --text-muted / --accent / --border / --shadow / --radius / --glass-blur / --glass-opacity`。
- `theme.ts`：`applyTheme(name)` 写 `dataset.theme` + localStorage；初始化读系统偏好。
- 防闪烁：`<head>` 内联脚本在 CSS 加载前应用已存主题。
- 扩展：新增主题 = 在 `themes.css` 加一段 + 在切换器加一个选项，**无需改组件**。

## 6. 数据层设计细节

- **策展数据**：Astro Content Collections（`src/content/*.json` 或 `.md`），用 Zod schema 校验，构建时类型安全。
- **动态数据**：`feeds.ts` 维护「源 → 板块」映射；客户端 `fetch` + `localStorage` 缓存（15 分钟）；多源并行 + 超时；失败回退缓存。
- **用户数据**：`store.ts` 封装收藏/进度/偏好；优先 IndexedDB，退化到 localStorage。
- **实时更新**：动态=运行时抓取；时间线=策展 +（可选）CF Cron 拉 AI 新闻自动追加。

## 7. 部署方案（二选一，建议 A）

### 方案 A：Cloudflare Pages（推荐）
- 仓库连 Cloudflare → push 自动部署；无限带宽、全球快。
- `wrangler.toml` 定义项目；`functions/` 放 CORS 代理与 Cron。
- GitHub Actions 用 `cloudflare/wrangler-action` + API Token（最小权限：仅 Pages Edit）。
- 自定义域名（Should）。

### 方案 B：GitHub Pages（最简/备用）
- 仓库开 Pages + `deploy.yml`（actions/checkout + build + upload‑pages）。
- 无函数能力；动态抓取依赖 CORS 友好源或 rss2json/allorigins 兜底。

### 方案 C：双站部署（已确认采用）
- **主站：Cloudflare Pages**（方案 A）—— 实时聚合、定时刷新、无限带宽、全球快。
- **备用副站：GitHub Pages**（方案 B）—— 同一份静态构建产物直接部署，作为容灾/镜像；Cloudflare 不可用时仍可访问。
- 实现：同一 `npm run build` 产物，分别由 `cloudflare/wrangler-action` 与 `actions/deploy-pages` 部署；CI 中两步相互独立，任一失败不影响另一。
- 主站绑自定义域名，副站用默认 `*.github.io`（也可另绑域名）。

> 三者都「push 即上线」，你无需管服务器。Agent 借助部署 Skill（cloudflare / github‑pages / publishing‑astro‑websites）完成配置。

## 8. 手机端协作流程（没电脑时怎么用）

1. **看站点**：手机浏览器直接访问公网 URL。
2. **改内容**（时间线/工具箱/读书）：手机浏览器登录 GitHub → 打开对应数据文件 → 点铅笔编辑 → 提交 → 自动上线。
3. **大改动**（重构/批量）：留到新年电脑，或交由 Agent 在沙箱改后你推送。
4. **部署**：推送即自动部署，你不用敲命令。

## 10. 风险与权衡（已识别）

- **CORS**：Cloudflare 方案用函数代理根除；GitHub Pages 方案用第三方代理（隐私/稳定性弱于前者）。→ 推荐 A。
- **公开源限流**：多源冗余 + 缓存 + 兜底。
- **玻璃性能**：低端机提供「减少动效/降低透明度」开关。
- **手机编辑大文件不便**：提供模板与示例，大改延后。
